# File and sidecar schemas

Audio events may declare `role:"workload"` for sustained activity, or `role:"cue"` for bounded timing templates; absent role retains cue semantics. The schedule keeps that explicit declaration. A workload's full signal remains in the native PCM reference but does not become one long timing cue or imply continuous waveform acceptance.

User audio events declare exactly one `frame` or `seconds` anchor. Seconds are nonnegative exact decimal/fraction values and must resolve to a whole frame at every selected FPS. Exported schedule fields remain native `file_frame`, reduced `pts`, `sample_index` and `sample_count`; no rounding or sample-rate substitution is introduced.

The app importer schema and VSG sidecar schemas are independent. All JSON is UTF-8; CSV has a header, comma delimiter and UTF-8 text. SHA256 means the actual file digest, including a WAV header when hashing the WAV file. PCM payload hashes are separately identified. Relative paths resolve against `raw-fixtures.json` and stay inside its directory.

`frames.csv` fields in order: `file_frame,frame_id,source_frame_id,source_frame,segment_id,pattern_id,repeat_index,pts_numerator,pts_denominator,i420_sha256,unmarked_i420_sha256,rgb_sha256,marked_rgb_sha256`. Integers use decimal text. A file-frame ID includes variant/mode/file-frame index. Source-frame identity hashes generator source, stable pattern/version/full parameters/seed/mode/local source index. Timeline repetition repeats source identity while creating different file-frame identity. Reduced rational PTS is `file_frame/fps`. File-loop iteration and stream generation are external harness facts.

`metrics.csv` fields in order: `file_frame,segment_id,si,ti,mean_absolute_delta,changed_fraction,entropy_bits,mean_luma,boundary,conditional_loop`. Empty values mean UNMEASURED; the first normal frame has no TI. Booleans are `True`/`False`. The last row has `segment_id:__file_loop__`, `file_frame:0`, `conditional_loop:True`; it compares last→first only if the consuming harness loops. Cuts/repeat seams/internal periodic seams/abrupt luminance boundaries are retained, with excluded-boundary temporal summaries. SI/entropy summaries contain only normal frames. Quantiles use linear interpolation and exact scalar ordering in disk-backed SQLite; no long sequence of frame arrays is retained.

Events carry `kind,file_frame,segment_id,pattern_id,source_frame,repeat_index`, reduced `pts`, and `audio_sample_index_48k`. A final conditional file seam uses `boundary_after_file_frame,next_file_frame,at_file_time` instead of inventing a new frame. Segment starts/motion transitions, hard cuts, repeats, internal period seams, rectangle changes, luminance changes, dissolve/fade starts and visual synchronization cues are represented. The audio schedule carries event ID, type, visual-anchor frame/PTS, exact start sample/count, frequency limits, amplitude, seed and rational sub-sample quantization error. User event durations are 48 kHz sample counts; other requested originals scale them by integer sample counts and use the same visual anchor.

The raw native layout is tightly packed Y rows (`width` bytes per row), followed by U then V rows (`width/2` bytes per row, `height/2` rows each). Its file size must be exactly `width*height*3/2*frame_count`. There is no raw file header. RGB24 is tightly packed R/G/B at `width*height*3` bytes per frame. These raw references require their associated metadata to be interpreted correctly. Marked and unmarked references can share paths when the external marker is disabled/unavailable.

Generated color is limited-range BT.709 I420 with centered chroma. RGB is full-range nonlinear BT.709 signal space. For native RGB code values, let `L=2126R+7152G+722B`. Luma is `16+round(219L/2550000)`. Cb is `128+round(224(10000B-L)/(255*18556))`; Cr uses R and 15748. Average the four native chroma numerators before final quantization. Rounding is integer `floor((n+d//2)/d)`, including negative numerators, with ties upward. This defines actual matrix/range/subsampling behavior rather than assigning tags to an implicit conversion. BT.709 transfer names describe the generated nonlinear signal; the renderer does not apply a second transfer function.

VSG1 payload is big-endian: uint16 magic `0x5653`, uint8 version 1, uint32 frame index, uint64 reduced PTS numerator, uint32 denominator, then uint32 CRC32 over the preceding 19 bytes. The 184 bits are each tripled, filling 23×24 interior cells in row order. The surrounding border yields 25×26 cells: top all white, bottom alternating from black, left black except the top, right alternating down the interior. Cells are an even native size ≥2. White/black RGB codes are 255/0; converted I420 Y is 235/16. Decoding checks cell means ≤80 or ≥175, rejects intermediate means or bad border, votes each triplet and verifies CRC/version/denominator. Bounds are half-open `(x,y,width,height)` at top-left. CRC detects errors; it is not an authentication scheme. Content masks exclude the union of all external/intrinsic marker bounds before rendering. Exact native decode is the tested scope; transformations/capture require a separate consumer adapter.

PCM metadata uses `vsg-pcm-reference-v1`: sample rate, channels, sample count, signed 16-bit little-endian format, PCM-only SHA256, measured peak, synthesis version and each event's identity/start/count in that file's clock. File SHA256 is in the manifest sidecar entry. Audio is chunked and stateless by sample index. Unknown imported video color fields are always `UNSPECIFIED`; luma metrics require a supported, evidenced range. No metadata is silently invented for imported references.

Seconds-based timeline segments compile independently per mode. Their provenance retains the exact declared `seconds`; resolved segment starts/counts use that mode's integer FPS without rounding. Multi-mode fixture variants share their original requested configuration/variant identity, and validation resolves the selected mode before checking counts/PTS. Frame-indexed parameters and explicitly repeated segments retain their existing semantics.

`vsg-panels-v1` contains `geometry:{width,height,fps}`, `segments:[{segment_id,file_frame_start,file_frame_end,source_frame_count,repeat,panels}]` and `content_roi`. Ends are exclusive. Each panel declares `id,pattern,pattern_id,bounds_xywh,seed,params,render_mode:"native",exclude_xywh`. Panel and exclusion rectangles are half-open native global coordinates; exclusions are intersections with the predeclared whole-file marker/cue mask. Panels never imply a quality pass or replace the whole-frame domain. Panel-local p39 events/audio and p40 marker tracks retain their panel ID and actual global coordinates.

`marker-layout.json` now carries `visual_cues` as null or `vsg-visual-cues-v1`: `status:"AVAILABLE",bounds_xywh,off_rgb,on_rgb,events,identity`. Each expected cue event declares `id,file_frame,pts,bounds_xywh,on_frames,rgb,duration_samples,frequency,end_frequency,amplitude`. Its fixed native ROI contributes to the whole-file exclusion union before rendering. `events.json.visual_cues` is identical, and matching `kind:"visual_sync"` rows carry `cue_id` and visual geometry; audio schedule IDs match. Unique defaults use a declared frequency progression rather than one repeated indistinguishable chirp. Actual stream generation/file-loop iteration and observed source/output times belong to the consumer, never to generated expectations.

Markers retain their original default top-left bounds. Framing timelines declare an even top-centre inset in `bounds_xywh`, with the same bounds in `content_roi.exclude_xywh`; rendering/decoding use those coordinates. Invalid chart/marker overlap is rejected. Intrinsic panel tracks declare global bounds, `segment_id` and `panel_id` in `intrinsic_tracks`.

`vsg-framing-calibration-v1` declares `width,height,pixel_aspect:[1,1],border:{thickness,rgb},landmarks:[{id,bounds,rgb}],square:{bounds,rgb},circle:{center,radius,rgb}`. The filled circle uses pixel-centre inclusion `(x+0.5-cx)^2+(y+0.5-cy)^2<=radius^2`. `reference:{path,sha256,format:"RGB24",file_frame:0}` points beside this sidecar to one exact executed marked frame; `source_file_frame` identifies its position in the original video. The manifest binds the pixel file as `calibration_reference` and this declaration as `calibration`. Marker/cue declarations coexist without replacing target geometry. No tolerance, detector-validation receipt or physical pass is generated.

`reference_mode:"native"` omits full `rgb_reference`/`marked_rgb` sidecars while retaining marked and unmarked I420 plus all original frame hashes. The validator rerenders original RGB to verify those hashes without requiring redundant disk copies. Optional framing still supplies the single RGB calibration reference. `reference_mode:"full"` remains the default with all previous reference roles. Changing package source/version changes the variant fingerprint; old references require their recorded old source for exact rerender validation.

Reports serialize identical-pixel PSNR as the string `inf`, never nonstandard JSON Infinity/NaN. Missing PSNR/SSIM/VMAF/unknown-range/cut-classification measurements are labelled UNMEASURED. SSIM is luma-only; pooled PSNR covers the specified plane/sample domain. Diagnostic payload CSVs use packet PTS and rational bin boundaries, include empty bins and distinguish packet payload from container bytes.
